# 記録・照合・計算結果の契約

T01「記録・照合・計算結果の契約」の成果物。関連Issue: [#8](https://github.com/doc-gif/kurashi-ledger/issues/8)。

- 契約版: `1.0`
- 状態: Proposed（このPRがmainに統合された時点で、後続タスクの前提にできる）

## この契約の役割

記録の種類ごとに、項目・型・意味を定める。合成データと期待結果（T03）、記録ドメイン（T06）、永続化（T07）、入力（T09・T10）、照合（T11）、出力（T12）、制度と計算（T14・T15〜T22）は、この契約の意味に従う。

- **定めること:** 記録の種類と項目、ID・版・単位・日付・通貨・金額の状態、3つの時間軸（適用期間・把握日・記録日時）、改訂と差し替え、照合配分と判断、集計の採用元、所得の年への帰属の根拠の持ち方、計算runの形。
- **定めないこと:** DBのテーブル（T07）、TypeScriptの型の書き方（T06）、CSV/JSONのファイル形式とデータ辞書（T12）、画面（T10）、税・保険の制度の規則（どの日付で年に帰属させるか、どの支給が課税か、年間資料のどの項目を明細のどの項目と比べるか。T14）。ただし、実装や出力は、この契約の区別（金額の4つの状態、日付の種類、改訂の履歴）を失ってはならない。

## 読む順序

1. [共通の型](common-types.md) — ID、版、金額・通貨・単位、金額の状態、日付と期間、時間軸、記録の区分、改訂、冪等キー、集計値の形
2. [記録の型](records.md) — 雇用先、雇用条件、口座、給与明細、銀行入金、年間資料、予測、正式通知、証憑、資料の差し替え、4つの日付
3. [照合・採用・集計の規則](reconciliation.md) — 集計の採用元、照合配分、照合の判断、年間資料と月次資料、予測の実績化、重複と同額別件、所得の年への帰属、改訂の影響
4. [計算結果](calculation-results.md) — 計算run、結果の状態、不変と再計算
5. [合成例](examples.md) — EX-01〜EX-08

## AGENTS.mdの不変条件との対応

| 不変条件 | 契約での扱い |
| --- | --- |
| 未知値は0ではない | 金額は4つの状態（値あり・不明・記載なし・対象外）を持つ。0は「値あり」の0だけ。集計は不足を数え、不足があれば合計として表示しない（[共通の型](common-types.md)の5・11） |
| 銀行入金は総支給額でも課税給与でもない | 入金は入金の集計にだけ使う。照合配分は金額を移さない（[照合の規則](reconciliation.md)の2・3） |
| 年間資料と月次明細を足して二重計上しない | 1つの集計に採用元は1つ。年間の値は、範囲の重ならない年間資料を採用する（[照合の規則](reconciliation.md)の5・10） |
| 実績・見込み・正式通知を分ける | 記録の区分を記録の種類で固定する。見込みは照合配分で実績化し、書き換えない（[共通の型](common-types.md)の8、[照合の規則](reconciliation.md)の6） |
| 適用期間・把握日・記録日・改訂履歴を保持する | 3つの時間軸と、追記だけの改訂（[共通の型](common-types.md)の7・9） |
| 過去の計算runを黙って書き換えない | 計算runは一度だけ書き、入力の版を固定する（[計算結果](calculation-results.md)の3） |
| 合成データのみ | 合成例はすべて架空（[合成例](examples.md)） |

## 契約の変更

- 契約定義（`docs/contracts/`）は共有資源。同時に変更するのは1担当だけにし、着手前に調整係へ申告する。
- 版は`メジャー.マイナー`。意味・状態の区別・値が必要かどうかを変える変更は、メジャーを上げる。省略時に`unknown`と解釈できる`Fact`の項目を足すだけなら、マイナーを上げる。列挙に値を足す変更は、既存の処理が知らない値を受け取るので、メジャーを上げる。
- 変更するPRは、影響するタスクの成果物（T03のケース、T06の不変条件、T07のmigration、T12のデータ辞書）を本文に挙げ、必要な追従を同じPRか後続のIssueで扱う。
- ADR（[docs/adr/](../adr/README.md)）と食い違う場合は、ADRを正とし、気づいた作業で契約を直す。
