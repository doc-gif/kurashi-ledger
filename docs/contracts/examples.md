# 合成例

[契約の入口](README.md)／前: [計算結果](calculation-results.md)

契約の規則を当てはめた結果を、合成データで示す。第三者が読んで、記録の持ち方と集計の結果を一通りに決められることを目的とする。T03は、これらの例を基にケースID・入力・期待する記録と集計・理由を台帳にする（例のIDを引き継いでよい）。

## 読み方

- **すべて架空のデータ。** 勤務先・口座・摘要・金額は、実在の人・会社・給与と関係がない。税額・保険料の値は、制度による計算の結果ではなく、例のために置いた数。
- 各例は独立している。記録のID（`pay_101`等）はその例の中だけで使う。下の「共通の設定」の雇用先・雇用条件・口座だけを共有する。
- 表に挙げない記録の項目は、その例の期待する結果に影響しない（実際の記録では、入力がなければ`unknown`になる）。
- 金額の状態は「値あり 230,000」「不明」「記載なし」「対象外」と書く（[共通の型](common-types.md)の5）。金額は円。
- 集計は「集計の種類（範囲、軸）」で書く。軸は、入金日・支払予定日・予定月・所得の年のどれか（[照合の規則](reconciliation.md)の2）。
- 「しないこと」は、この契約のもとで誤りになる解釈。

| 集計 | 結果 |
| --- | --- |
| 入金額（口座1、入金日 2026-09） | `complete` 182,000（手順1から変わらない） |
| 支給額（勤務先A、支払予定日 2026-09） | `complete` 230,000（`pay_101`の`grossPay`） |
| 源泉徴収税額（勤務先A、支払予定日 2026-09） | `complete` 4,000 |

- 証憑`evf_101`を紐付けても、金額は増えない。

## EX-03 同じ日・同じ金額の別件

勤務先Bから、2026-10-30に口座2へ30,000の入金が2件あった。1件は9月勤務分の給与、もう1件は立て替えた経費の精算。

| ID | 種類 | 内容 |
| --- | --- | --- |
| `dep_301` | 銀行入金 | 口座2、2026-10-30、30,000、摘要「フリコミ ビーシヤ（架空）」、`purpose` 給与の振込。`writeRequestId` `w-301` |
| `dep_302` | 銀行入金 | 口座2、2026-10-30、30,000、摘要「フリコミ ビーシヤ（架空）」、`purpose` 経費の精算。`writeRequestId` `w-302` |
| `pay_301` | 給与明細 | 勤務先B、給与、勤務期間 2026-09-01〜2026-09-30、支払予定日 2026-10-30、総支給額 33,000、所得税 3,000、振込額 30,000 |
| `dcs_301` | 照合の判断 | `duplicate-review`、対象 `dep_301`・`dep_302`、`distinct`、理由「給与と経費の精算の別の振込（勤務先に確認）」 |
| `alc_301` | 照合配分 | `pay_301` → `dep_301`、30,000、確定 |

手順と結果:

1. `dep_301`の保存の要求が、通信の再送で2回届いた（同じ`w-301`）。記録は`dep_301`の1件だけ。2回目の要求には、1回目と同じ結果を返す。
2. `dep_302`は別の操作（`w-302`）なので、口座・日付・金額が同じでも別の記録として保存する。`dep_301`との組が重複の候補として表示される（保存は止めない）。
3. 利用者が`dcs_301`（別件）を記録する。この組は候補に出なくなる。
4. `alc_301`で給与の明細と`dep_301`を結ぶ。

| 集計 | 結果 |
| --- | --- |
| 入金額（口座2、入金日 2026-10） | `complete` 60,000 |
| 支給額（勤務先B、支払予定日 2026-10） | `complete` 33,000（`pay_301`だけ） |
| 未照合の入金 | `dep_301`: 0、`dep_302`: 30,000（経費の精算。給与ではないので未照合のまま残る） |

二重登録の場合: 後日、利用者が同じ入金を手入力でもう一度保存した（別の操作`w-303`で`dep_303`、口座2、2026-10-30、30,000）。

| 時点 | 入金額（口座2、入金日 2026-10） | 表示 |
| --- | --- | --- |
| `dep_303`の保存直後 | `complete` 90,000 | 重複の候補2組（`dep_301`と`dep_303`、`dep_302`と`dep_303`） |
| `dcs_302`（`duplicate-review`、対象 `dep_301`・`dep_303`、`same`）を記録し、`dep_303`を取消（版2、`void`、`duplicateOf` `dep_301`）した後 | `complete` 60,000 | `dep_303`は履歴に残る。`dcs_302`は有効のまま（取消した`dep_303`の`duplicateOf`が判断のもう一方`dep_301`を指すため。[照合の規則](reconciliation.md)の7） |

同じ証憑のPDFを2回取り込んだ場合、`sha256`が同じなので証憑ファイルは1件（`evf_301`）だけ。

しないこと: 口座・日付・金額が同じことだけで、保存を拒否したり自動で統合したりしない。`dep_302`を給与の集計に入れない。再送で2件の記録を作らない。

**新しい情報で状態が変わる場合:** 後日（把握日 2026-12-05）、勤務先Bから「雇用保険には加入していない」と回答を得た。`pay_801`・`pay_802`を改訂（`new-information`、把握日 2026-12-05、`changeNote`「勤務先Bの回答」）して、雇用保険料を対象外にする（明細とは別の情報源による変更なので`correct-input-error`ではない。[記録の型](records.md)の4）。`term_2`の雇用保険も、同じく`new-information`で「不明」から「未加入」に改訂する。雇用保険料の集計は`not-applicable`（対象外）になる。把握時点の再現（2026-12-01）では、版1（把握日 2026-10-28・2026-11-27）が選ばれ、記載なしのまま。

しないこと: 不明・記載なしを0として足さない。所得税の集計を「3,000円」と表示しない。住民税の0円を「不明」と表示しない。対象外を不足として数えない。記載なしを、確かめる前に対象外へ変えない。
